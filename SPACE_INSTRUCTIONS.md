# 📋 Инструкция для рабочего пространства

Этот файл описывает правила работы с репозиторием smart-project-map в рамках AI-сессий.

---

## 🗂 Структура репозитория — где что смотреть

| Файл / Папка | Назначение |
|---|---|
| `README.md` | Краткое описание проекта, структура слоёв, roadmap |
| `CONCEPT.md` | **Главный документ.** Подробное описание каждого слоя: назначение, обоснование решений, технологии, структура файлов, типы |
| `CHANGELOG.md` | Лог всех изменений по сессиям. Только дополняется, никогда не перезаписывается |
| `SPACE_INSTRUCTIONS.md` | Этот файл. Правила работы с репозиторием |
| `package.json` | npm workspaces — корневой манифест |
| `layer-0-cli/` | Слой 0: CLI, file watcher, точка входа |
| `layer-1-parser/` | Слой 1: статический анализ кода |
| `layer-2-graph/` | Слой 2: построение графа зависимостей |
| `layer-3-server/` | Слой 3: Fastify API + WebSocket |
| `layer-4-ui/` | Слой 4: браузерный интерфейс |
| `layer-5-dataflow/` | Слой 5: DataFlow Visualizer (killer feature) |
| `shared/` | Общие TypeScript-типы и утилиты для всех слоёв |

## ✏️ Правила редактирования CONCEPT.md

### Принцип: правим, не переписываем

- **Изменение слоя** → правится только раздел этого слоя в `CONCEPT.md`. Остальные разделы не трогаются.
- **Добавление нового решения** → дописывается в нужный раздел, старое решение не удаляется, а помечается или заменяется с пояснением.
- **Никогда** не удалять весь файл и не создавать заново — только точечные правки через patch.
- Если меняется тип из `shared/` → обновляются все разделы, которые на него ссылаются.

### Как говорить AI что менять

```
✅ Правильно:
"Измени Layer 1 — добавь поддержку Rust"
"В Layer 3 замени SSE на WebSocket как основной вариант"
"В shared/ добавь поле language в тип ServiceNode"

❌ Неправильно:
"Перепиши концепт"
"Удали старый концепт и напиши новый"
```

## 📝 Правила ведения CHANGELOG.md

### Структура записи

```markdown
## [YYYY-MM-DD] — Краткое описание сессии

### Добавлено
- ...

### Изменено
- ...

### Зафиксировано в репо
- ...
```

### Правила

1. **Changelog только дополняется** — новые записи добавляются сверху (новейшее вверху)
2. **Никогда не удалять** старые записи
3. **Одна запись на сессию** — дата + краткое резюме что сделано
4. **Размер файла**: если `CHANGELOG.md` превышает ~300 строк — создаётся `CHANGELOG-v2.md`, и так далее. Старый файл не трогается, в шапке нового — ссылка на предыдущий.
5. **Фиксировать в конце каждой сессии** — AI добавляет запись перед завершением работы

### Пример ротации

```
CHANGELOG.md        ← текущий (до ~300 строк)
CHANGELOG-v2.md    ← когда первый вырастет
CHANGELOG-v3.md    ← и так далее
```

## 🔄 Правила работы по слоям

- Каждый слой — отдельный каталог (`layer-N-name/`)
- При реализации слоя — сначала обновляется `CONCEPT.md` (раздел слоя), затем пишется код
- Изменения в `shared/` согласовываются отдельно — они затрагивают все слои
- Каждый коммит в репо имеет префикс: `feat:`, `fix:`, `docs:`, `refactor:`

---

## 📌 Порядок обсуждения слоёв

Рекомендуемый порядок реализации (по зависимостям):

```
shared/ → layer-1-parser → layer-2-graph → layer-3-server → layer-4-ui → layer-5-dataflow
```

Layer 0 (CLI) реализуется параллельно с layer-3-server, так как зависит только от него.
